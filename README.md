# Бот-квиз: какой продукт нужен бизнесу

[![CI](https://github.com/CaravanHouse/quiz-bot/actions/workflows/ci.yml/badge.svg)](https://github.com/CaravanHouse/quiz-bot/actions/workflows/ci.yml)

Пять вопросов в Telegram, и бот советует: бот, сайт, мини-апп или связку. Затем предлагает оставить номер, и заявка уходит вам.

**Что показывает клиенту:** как бот сам ведёт диалог и приносит заявки. Подходит как первый контакт с аудиторией.

## Что внутри
- Вопросы и баллы в `src/quiz.ts`: меняйте тексты и вес ответов без правки логики
- Одно сообщение редактируется на месте, есть прогресс-бар
- Защита от двойных тапов и старых сообщений
- Номер принимается только свой (кнопка «Поделиться номером»)
- Админу приходит заявка с результатом квиза, `/stats` показывает воронку: начали, дошли до конца, заявки

## Запуск
```bash
npm install
cp .env.example .env     # BOT_TOKEN, ADMIN_CHAT_ID
npm start
```
Тесты: `npm test`. Бот работает на long polling, поэтому отдельный домен не нужен.

## Деплой на Railway
Сначала задеплойте `configurator`: его адрес нужен для кнопки «Посчитать смету».

1. **New Project → Deploy from GitHub** → этот репозиторий. Сборка не нужна. Команда запуска и автоперезапуск описаны в `railway.json`.
2. **Подключите Volume** с путём `/data`. Без него статистика, заявки и незавершённые квизы стираются при каждом деплое.
3. **Variables:** `BOT_TOKEN`, `ADMIN_CHAT_ID` (напишите боту `/id`), `CONFIGURATOR_URL` (адрес конфигуратора, можно без `https://`), `DATA_DIR=/data`.
4. Оставьте **1 реплику**: бот на long polling, а Telegram разрешает только одно подключение к боту. Вторая копия получит ошибку 409 Conflict, а данные в JSON-файле затрут друг друга.

Публичный домен боту не нужен. Для каждого проекта нужен **свой бот** в @BotFather.

## Данные
Статистика, заявки и незавершённые квизы хранятся в JSON-файлах в папке `DATA_DIR` (по умолчанию `./data`). При большой нагрузке переходите на PostgreSQL.
